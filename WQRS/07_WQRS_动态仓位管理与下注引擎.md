**WQRS V4.1 — Ch07 Dynamic Position Sizing & Betting Engine V3.4**

> 2. 统一加仓决策边界：Ch07 是加仓股数的唯一计算方，触发条件来自 Ch06 的 `add_position_permitted: true`

---

## 7.1 核心定位

```
仓位系统 = 风险预算的物理化执行层
```

Ch07 是整个 WQRS 系统的"弹药库"：宏观决定是否交易，行业决定做哪个方向，基本面决定做哪只标的，信号决定何时进入，**仓位决定做多少**。

---

## 7.2 风险预算基础

```
R = Total_Asset × 1%
```

这是单笔交易的**最大允许亏损金额**，所有仓位计算以此为出发点。

---

## 7.3 核心仓位生成链

### Step 1：风险原始仓位

```
Shares_raw = R / ΔP
```

其中 `ΔP = 入场价 - 止损价`（来自 Ch06 的 `stop_loss_price`）

### Step 2：凯利调整（V4.1 完整版）

**凯利系数计算：**

```
p = historical_win_rate        （来自 Ch06 输出）
b = historical_rr_ratio        （来自 Ch06 输出）
q = 1 - p

Full_Kelly = (p × b - q) / b
Half_Kelly = Full_Kelly × 0.5  （安全压缩）
W_adjust   = clamp(Half_Kelly, 0.1, 1.0)
```

**W_adjust 含义：**
- `1.0` = 满额使用 1% 风险预算
- `0.1` = 极轻试探仓（信号质量极低时）

**与 signal_quality_score 的对应关系（用于校验）：**

| signal_quality_score | 典型 W_adjust 范围 |
|---|---|
| ≥ 90 | 0.75–1.00 |
| 80–89 | 0.55–0.75 |
| 70–79 | 0.40–0.55 |
| < 70 | 不接收信号 |

**禁止使用固定 W_adjust 值**，每笔信号必须通过上述公式动态计算。

```
Shares_kelly = Shares_raw × W_adjust
```

### Step 3：系统风控回写

必须通过 Portfolio Revalidation Engine，检查：

- 单股暴露 ≤ 10%
- 行业暴露 ≤ 30%
- 系统风险 ≤ 5%

任意一项超标 → 自动压缩 `Shares_kelly` 至合规值。

### Step 4：A股100股取整（最终执行）

```
Final_Shares = floor(Shares_kelly / 100) × 100
```

## 7.4 初始仓位结构

Ch06 的信号确认后，Ch07 计算的初始仓位为**目标仓位的 30%**（首笔建仓），剩余 70% 通过金字塔加仓机制分批入场。

---

## 7.5 金字塔加仓系统（V4.1 修订版）

### 触发条件

加仓的触发信号**唯一来源**是 Ch06 输出的 `add_position_permitted: true`，Ch07 不自行判断加仓时机。

**Ch07 在收到 `add_position_permitted: true` 后，还须同时验证：**
- 浮盈中（当前价 > 加权成本价）
- 当前价在 VWAP 上方
- 动态均价止损条件成立
- 风控重算通过（Step 3）

**任意一项不满足 → 加仓拒绝，即使 Ch06 已发出 `true`。**

### 加仓比例结构（对应 Ch06 的触发阈值）

| Ch06 触发 | 加仓占目标仓位比例 | 说明 |
|---|---|---|
| 初始建仓 | 30% | 信号确认时 |
| 第一次许可（+8%浮盈）| 50% | 趋势确认加码 |
| 第二次许可（+15%浮盈）| 20% | 趋势延续末端 |
| **合计** | **100%** | 目标仓位全满 |

> 每次加仓的实际股数均通过凯利公式重新计算（使用最新的 `historical_win_rate` 和当前 `ΔP`），而非固定比例截断。

### 加仓强制规则

每次加仓必须执行：
- ✔ 重新计算仓位占比
- ✔ 重新跑 Step 3 风控
- ✔ 重新验证系统风险

### 止损规则（修复版）

```
Stop_Loss = max(初始止损价, 动态加权成本均价)
```

金字塔加仓后，止损线**必须上移**至新的动态均价，彻底根绝"账面保本、实际亏损"陷阱。

---

## 7.6 风险防火墙

| 约束 | 上限 |
|---|---|
| 单股暴露 | ≤ 10% |
| 行业暴露 | ≤ 30% |
| 系统风险（未脱险总仓位）| ≤ 5% |

以上约束为**硬性红线**，任何计算结果违反时系统自动回写压缩，不允许人工覆盖。

---

## 7.7 凯利系数的滚动更新机制

| 阶段 | p / b 来源 |
|---|---|
| 初期（< 90个交易日历史）| 使用 Ch06 的分级默认值（按 signal_quality_score 映射）|
| 正式运行（≥ 90个交易日）| 使用实际滚动统计值，每日盘后更新 |

**分类统计**：A容器成长股、B容器红利股、C容器ETF 分别维护独立的胜率/赔率统计池，避免混淆。

## 7.9 本章终极结论

仓位系统 = 风险的物理执行器 + 数学约束终端

**六层闭环：**

```
宏观     → 是否交易
行业     → 做哪个方向
基本面   → 做哪只标的
信号     → 何时进入（+加仓许可 YES/NO）
仓位     → 做多少（凯利计算）
执行     → 是否成交
```

V4.1 核心升级：凯利系数从"黑盒固定值"升级为**可追溯、可更新、有来源的动态计算**，是仓位管理引擎从"写得通"到"跑得准"的关键一步。
