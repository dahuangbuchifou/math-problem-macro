# WQRS V4.1 数字化量化投研系统开发总纲
> **版本**：V4.1 | **修订说明**：在V4.0基础上修复六项跨模块接口缺口，强化凯利系数输入链路、B/C容器信号补全、加仓边界统一、白名单联动、极端状态权重自适应、GTSM紧急接管规则。

---

## 系统定位

一个基于宏观状态自适应、严格风险预算、以及机构级算法执行的个人量化投研与自动化交易框架。

**核心信仰**：风控优先于收益，概率胜于预测，纪律战胜人性。

---

## 一、系统全局拓扑与职责边界

WQRS 采用自上而下的**六层漏斗架构**，模块之间单向解耦，通过标准 JSON 协议传递指令，**严禁下层模块越权修改上层风控参数**。

| 模块层级 | 核心组件 | 系统职责 | 输入 | 输出 |
|----------|----------|----------|------|------|
| 1. 哲学层 | Ch01 投资哲学 | 确立系统价值观与不交易原则 | 市场底层数据 | 绝对生存红线 |
| 2. 宏观层 | Ch02 宏观引擎 | 总闸门：判断市场状态，决定总敞口 | 高低频宏观/流动性因子 | 仓位硬上限（如80%或0%）|
| 3. 资产层 | Ch03 资产配置 | 资金分配：跨容器风险平价 | 宏观状态与上限 | 各容器资金预算 |
| 4. 中观层 | Ch04 行业轮动 | 寻矿器：剔除拥挤赛道，寻找资金与景气共振 | A容器资金预算 | 目标行业清单与预算再分配 |
| 5. 微观层 | Ch05 基本面引擎 | 排雷网：财务造假一票否决，估值质量综合打分 | 目标行业内个股池 | 干净个股白名单（含行业联动状态） |
| 6. 战术层 | Ch06 信号引擎 | 发令枪：RPS动量与VCP突破，B/C容器独立信号链 | 个股白名单+K线数据 | 精确买卖信号（含信号质量评分） |
| 7. 算力层 | Ch07 仓位管理 | 弹药库：1%风险模型与凯利压缩，精确算股 | 买卖信号+信号质量评分 | 具体下注股数JSON |
| 8. 执行层 | Ch08 状态机 | 终结者：GTSM全局状态机，冰山拆单，对抗滑点 | 合规交易JSON指令 | 实盘订单API路由与成交审计日志 |

## 二、系统级绝对风控红线

> 这些是在代码开发中必须写在底层拦截器（Interceptor）中的强制断言（Asserts），任何逻辑违反以下规则，系统即刻触发内核级熔断。

### 暴露度控制红线

- **单笔风险熔断**：单笔交易最大绝对损失 ≤ 总资产净值的 1%
- **个股集中度**：单一股票名义本金总暴露 ≤ 总资产净值的 10%
- **行业集中度**：单一申万一级行业总暴露 ≤ 总资产净值的 30%
- **未脱险总敞口**：处于浮亏或止损未上移至保本线的总仓位风险 ≤ 5%

### 物理执行与数学红线

- **凯利压缩原则**：凯利调节系数 `W_adjust` 仅做向下压缩，约束范围强锁在 [0.1, 1.0]，绝不允许放大1%初始风险
- **凯利输入来源**（V4.1新增）：`W_adjust` 必须由 Ch06 输出的 `signal_quality_score` 与 `historical_win_rate` 计算得出，禁止使用固定常数
- **物理手数量化**：最终执行股数必须是凯利系数调整后，执行向下取整的100股整数倍
- **动态均价止损**：金字塔加仓后，止损线必须上移至 `max(初始止损价, 最新动态加权成本均价)`
- **加仓决策边界**（V4.1新增）：加仓许可信号由 Ch06 发出（YES/NO），加仓股数计算权力归属 Ch07，两层职责不得混用

### 跨模块联动红线（V4.1新增）

- **行业退出联动**：Ch04 输出 `dropped_sectors` 时，Ch05 必须将对应行业内白名单股票状态置为 `watchlist_suspended`，Ch06 对该状态股票禁止新信号
- **极端状态接管**：Ch08 极端盘面拦截网触发时，GTSM 向 Ch07 注入 `EMERGENCY_OVERRIDE` 信号，接管止损执行路径，结果写入审计日志

## 三、全局异常与黑天鹅响应矩阵

| 异常触发场景 | GTSM 指令与系统动作 |
|-------------|-------------------|
| 个股封死涨停 | 拒绝排队，放弃VCP信号，直接撤单归档，防范炸板诱多 |
| 个股跌停开盘 | 绕过冰山拆单，09:29:59 用跌停价全仓抢跑集合竞价队列 |
| 系统性闪崩（指数30分钟跌 >2.5% 或3只个股同步跌停） | 全局买入与加仓接口物理断电，算力仅保障撤退与止损 |
| 柜台软失败（滑点过大/未成交） | 撤单后进攻性滑点补偿重新挂单，最多重试3次，超限作废为DEAD_ORDER |
| 柜台硬失败（非法标的/资金不足） | 绝对禁止重试，直接写入DEAD_ORDER并触发警报 |

## 四、核心数据流与执行时钟

| 时段 | 动作 |
|------|------|
| 盘后结算（15:30-18:00） | 拉取全市场日线、财务、宏观数据；驱动Ch02~Ch05，更新次日宏观预算、目标行业与白名单 |
| 盘前竞价（09:15-09:25） | 监控跌停黑天鹅，执行抢跑逃生逻辑 |
| 极速攻击期（09:30-09:45） | 停止冰山算法；仅允许突破追价与隔夜止损 |
| 隐蔽潜行期（10:00-14:30） | 开启TWAP/VWAP建仓路由，拆单间隔3000ms-7000ms |
| 尾盘清扫期（14:50-14:57） | 撤销所有PARTIAL_FILLED残单，集合竞价跨价单终极出清 |
