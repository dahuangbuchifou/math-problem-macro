## 6.1 设计定位

本章是 WQRS 的"执行触发层"，本质是：

```
价格行为 + 成交结构 + 宏观状态 → 交易许可系统
```

**核心职责：**
- 决定是否允许交易
- 决定是否允许加仓（YES/NO）
- 决定是否允许退出
- 对赔率进行涨跌停截断修正（V4.2 新增）

**不做任何预测，不做任何选股。**

---

## 6.2 Signal Router（信号路由器）

三大容器路径各自独立，信号规则不同：

| 容器 | 信号逻辑 |
|---|---|
| A容器（Growth）| RPS + 趋势 + 收缩结构 + 突破 |
| B容器（Income）| 股息率 + 均线支撑 + 低波动 |
| C容器（Macro）| 宏观因子触发 + 商品趋势 + 资金流 |

---

## 6.3 Regime Override Layer（宏观总开关）

来自 Ch02，权限最高，任何信号不得突破：

| 宏观状态 | 开仓权限 |
|---|---|
| Euphoria | 100%（但 R/R 要求≥3） |
| Risk On | 100% |
| Risk Neutral | 70% |
| Risk Off | 30%，降低信号密度 |
| Panic | 禁止开仓 |
| Capitulation | 禁止开仓，只允许减仓 |

---

## 6.4 白名单状态检查（V4.1 新增）

在生成任何新开仓信号前，**必须检查** Ch05 输出的 `whitelist_status` 字段：

| whitelist_status | 信号处理 |
|---|---|
| `active` | 允许生成信号 |
| `watchlist_suspended` | **拒绝新开仓信号**，存量仓位正常执行退出逻辑 |
| `fraud_review` | 拒绝所有信号 |
| `expired` | 拒绝，等待 Ch05 重评完成 |

## 6.5 Intraday Filter（V4.2 修订）

### 交易窗口规则（V4.2 统一修订版）

| 时段 | 名称 | 规则 |
|------|------|------|
| 09:25-09:30 | 集合竞价 | 仅执行隔夜/T+1锁定抢跑单，不参与竞价博弈 |
| 09:30-09:45 | 极速止损期 | **仅允许隔夜持仓止损单，禁止一切新开仓（含突破追价）** |
| 09:45-10:00 | 噪音过滤期 | 禁止所有新开仓，等待价格结构稳定 |
| 10:00-14:30 | 正常交易期 | 按正常规则生成信号 |

> **V4.2 核心变更**：消除了 V4.1 中 Ch00「09:30-10:00 禁止新开仓」与 Ch08「09:30-09:45 允许突破追价」的矛盾。现统一为：09:30-10:00 全程禁止新开仓，09:30-09:45 仅允许止损单。突破追价等待至 10:00 之后。

### VWAP 确认机制

BUY 条件必须满足：
- `Price > VWAP` 持续 ≥ 15分钟
- 价格不能跌破 `VWAP ± 0.3%`（防假突破）

### 分时量能结构

使用 10:00 之后数据（去除早盘污染）：

```
V_10:00–10:30 > 1.3 × MA20(同时间窗均值)
```

## 6.6 A容器信号规则（Growth 成长突破）

### 三阶段结构

**① RPS 过滤**
- RPS120 ≥ 80
- RPS250 ≥ 80

**② 简化 VCP（收缩结构确认）**
- 股价在52周高点 20% 以内
- 60日波动率下降
- 成交量收缩

**③ 突破确认**
- `Price > Pivot`
- `Volume > 1.5 × MA20`
- MA 多头排列

### 初始建仓与加仓许可

初始仓位：目标仓位的 30%（具体股数由 Ch07 计算）

加仓许可条件（V4.1 修订）：

| 浮盈幅度 | `add_position_permitted` |
|---|---|
| +8% | `true`（第一次加仓许可）|
| +15% | `true`（第二次加仓许可）|
| 未达阈值 | `false` |

> **重要**：Ch06 只输出 `true/false`，**不定义加仓比例**。具体加仓股数全部由 Ch07 仓位管理引擎计算。

**加仓前提（必须同时满足）**：浮盈中、VWAP 上方、未触发风险信号、Ch05 白名单状态为 `active`。

## 6.7 B容器信号规则（Income 红利防御）— V4.1 新增，V4.2 维持

### 入场条件

**基础条件（必须同时满足）：**
- 股息率 ≥ 3.5%（当前滚动股息率）
- 股价在60日均线上方
- 近60日波动率低于市场均值
- `whitelist_status = active`

**加分条件（满足任意1项）：**
- 近1年股息连续增长
- PB < 历史60%分位
- 经营现金流 / 净利润 > 1.0

### 出场条件

| 触发事件 | 动作 |
|---|---|
| 股价跌破 60 日均线 | 减仓 50% |
| 股价跌破 120 日均线 | 全部清仓 |
| 季报披露股息削减 > 20% | 强制全部清仓 |
| 宏观状态变为 Panic | 降至最低观察仓（≤2%）|

### 加仓许可

B容器无追涨加仓逻辑，仅在以下情形允许加仓：
- 股息率因股价下跌进一步提升至 ≥ 4.5%
- 且股价仍在 60 日均线上方

输出：`add_position_permitted: true/false`，股数由 Ch07 计算。

## 6.8 C容器信号规则（Macro 宏观对冲）— V4.1 新增，V4.2 维持

### 入场触发条件

C容器（黄金ETF/资源类）的入场信号**直接挂钩 Ch02 宏观因子**，满足以下任意2项触发：

| 宏观指标 | 触发阈值 |
|---|---|
| DXY（美元指数）30日跌幅 | > 2% |
| 中国10年期国债收益率 30日降幅 | > 15bp |
| M2 同比增速环比上升 | 连续2个月 |
| 宏观状态降级（Risk On → Neutral 或以下）| 触发 |

**同时满足技术确认：**
- 对应 ETF 价格在 20 日均线上方
- 近20日成交量相对放大（> 1.2× MA20）

### 出场条件

| 触发事件 | 动作 |
|---|---|
| DXY 30日涨幅 > 3% | 减仓 50% |
| 宏观状态回升至 Risk On | 逐步减仓（分3周线性减仓）|
| ETF 价格跌破 60 日均线 | 全部清仓 |

### 加仓许可

当宏观状态处于 Risk Off 或 Panic 时，C容器权重上调，允许补仓：
- 输出 `add_position_permitted: true`
- 加仓上限由 Ch03 资产配置的 C容器权重约束，股数由 Ch07 计算

## 6.9 Exit Matrix（退出矩阵）

退出信号优先级（高到低）：

```
风险退出 > 宏观退出 > 基本面退出 > 买入信号 > 加仓信号
```

| 退出类型 | 触发条件 | 动作 |
|---|---|---|
| A 技术退出 | 跌破 20MA | 清仓 |
| B 基本面退出 | 财务红旗触发 | 强制退出 |
| C 宏观退出 | Risk Off | 降仓；Capitulation → 禁止开仓 |
| D 白名单降级退出 | `watchlist_suspended` + 跌破 20MA | 清仓 |

## 6.10 信号质量评分体系（V4.1 新增，V4.2 扩展）

### 设计目的

为 Ch07 凯利系数提供 `p`（胜率）和 `b`（赔率）的估算输入，解决凯利输入端空洞问题。

### Signal Quality Score 计算

```
signal_quality_score (0-100)
= 40% × RPS强度分
+ 30% × VCP质量分
+ 20% × 宏观适配分
+ 10% × 估值安全垫分
```

| 维度 | 说明 |
|---|---|
| RPS强度分 | RPS120分位直接映射（RPS90→100分，RPS80→80分）|
| VCP质量分 | 波动率收缩幅度 + 突破量能倍数 |
| 宏观适配分 | Risk On=100，Neutral=70，Risk Off=30 |
| 估值安全垫分 | PB历史分位越低分数越高 |

### 历史胜率与赔率

- `historical_win_rate`：按标的类型（A容器成长股/B容器红利/C容器ETF）分别统计近**90个交易日**实际信号胜率，初期无数据时使用分类默认值
- `historical_rr_ratio`：对应类型近90日实际盈亏比均值

**初期默认值（无足够历史数据时）：**

| signal_quality_score | 默认 p | 默认 b | 对应 W_adjust |
|---|---|---|---|
| ≥ 90 | 0.60 | 2.8 | 0.82 |
| 80–89 | 0.55 | 2.4 | 0.65 |
| 70–79 | 0.50 | 2.0 | 0.50 |
| < 70 | 不发信号 | — | — |

### 赔率截断修正（V4.2 新增）

A股涨跌停制度会截断真实盈亏分布，导致理论赔率 b 被高估。Ch06 在输出 b 值前必须进行截断修正：

```python
def compute_b_adjusted_for_limits(entry_price, stop_loss, target_price, 
                                   limit_down, limit_up):
    """修正A股涨跌停对赔率的截断效应"""
    b_raw = (target_price - entry_price) / (entry_price - stop_loss)
    
    # 止损价触及跌停：真实亏损可能更大（次日在更低价位成交）
    if stop_loss <= limit_down * 1.005:
        b_raw *= 0.80
        # 记录：stop_at_limit_down 修正
    
    # 目标价触及涨停：真实盈利可能被涨停截断
    if target_price >= limit_up * 0.995:
        b_raw *= 0.90
        # 记录：target_at_limit_up 修正
    
    return b_raw
```

| 截断场景 | 修正系数 | 原因 |
|---------|---------|------|
| 止损价触及跌停价 | b × 0.80 | 次日竞价可能以更低价格成交，真实亏损大于理论值 |
| 目标价触及涨停价 | b × 0.90 | 涨停封板导致无法全部在高位卖出，真实收益小于理论值 |
| 两者同时触及 | b × 0.72 | 叠加修正 |

> **重要**：修正后的 b 通过 `b_adjusted_for_limits` 字段传递给 Ch07。Ch07 的凯利计算应**优先使用修正后的 b**（当 `b_adjusted_for_limits` 存在时），而非原始的 `historical_rr_ratio`。

## 6.11 输出接口（V4.2 完整版）

```json
{
  "protocol_version": "4.2",
  "signal": "BUY_CONFIRMED",
  "container": "A",
  "ticker": "600519",
  "signal_quality_score": 84,
  "historical_win_rate": 0.57,
  "historical_rr_ratio": 2.5,
  "b_adjusted_for_limits": 2.0,
  "b_limit_adjustment_reason": "target_at_limit_up",
  "add_position_permitted": false,
  "vwap_ok": true,
  "volume_window_ok": true,
  "intraday_block": false,
  "macro_state": "Risk On",
  "whitelist_status": "active",
  "stop_loss_price": 1680.0,
  "timestamp": "2026-06-03T10:32:00"
}
```

**字段说明：**

| 字段 | 版本 | 说明 |
|------|------|------|
| `protocol_version` | V4.2 新增 | JSON 协议版本号，下游模块校验兼容性 |
| `signal_quality_score` | V4.1 | 信号质量综合评分（0-100），Ch07 凯利计算输入 |
| `historical_win_rate` | V4.1 | 近90日历史胜率，Ch07 的 `p` 值 |
| `historical_rr_ratio` | V4.1 | 近90日历史盈亏比（原始值，仅供参考） |
| `b_adjusted_for_limits` | **V4.2 新增** | 经涨跌停截断修正后的盈亏比，Ch07 **应优先使用此值** |
| `b_limit_adjustment_reason` | **V4.2 新增** | 修正原因：`none` / `stop_at_limit_down` / `target_at_limit_up` / `both` |
| `add_position_permitted` | V4.1 | 加仓许可（`true/false`） |
| `whitelist_status` | V4.1 | 白名单状态，透传供审计 |

## 6.12 本章总结

信号引擎 = 交易许可系统 + 噪声过滤器 + 宏观门禁 + 质量评分输出层 + 赔率修正层

V4.2 核心升级：**涨跌停赔率截断修正 + 交易窗口统一 + 协议版本化**，确保信号引擎输出的 b 值反映 A 股真实交易约束。

V4.1 核心升级：三容器信号规则完整化 + 凯利输入接口补齐 + 加仓决策边界统一。
