# WQRS V4.1 数字化量化投研系统开发总纲
**System Blueprints — 修订版 V4.1**

> **修订说明（V4.0 → V4.1）**：本次修订整合了六项系统性优化，核心变更包括：Ch06 输出接口新增信号质量字段（解决 Ch07 凯利输入端空洞）、Ch06 补齐 B/C 容器信号规则、统一 Ch06/Ch07 加仓决策边界、Ch04→Ch05 行业退出联动白名单降级、Ch04 极端状态权重自适应、Ch08 紧急接管优先级明确化。

---

## 系统定位

一个基于宏观状态自适应、严格风险预算、以及机构级算法执行的个人量化投研与自动化交易框架。

**核心信仰：风控优先于收益，概率胜于预测，纪律战胜人性。**

---

## 一、系统全局拓扑与职责边界

WQRS 采用自上而下的六层漏斗架构，模块之间单向解耦，通过标准 JSON 协议传递指令，**严禁下层模块越权修改上层风控参数**。

| 模块层级 | 核心组件 | 系统职责 | 输入 | 输出 |
|---|---|---|---|---|
| 1. 哲学层 | Ch01 投资哲学 | 确立系统价值观与不交易原则 | 市场底层数据 | 绝对生存红线 |
| 2. 宏观层 | Ch02 宏观引擎 | 总闸门：判断市场状态，决定总敞口 | 高低频宏观/流动性因子 | 仓位硬上限（如 80% 或 0%）|
| 3. 资产层 | Ch03 资产配置 | 资金分配：跨容器风险平价 | 宏观状态与上限 | 各容器资金预算 |
| 4. 中观层 | Ch04 行业轮动 | 寻矿器：剔除拥挤赛道，寻找资金景气共振 | A容器资金预算 | 目标行业清单与预算；**dropped_sectors 列表** |
| 5. 微观层 | Ch05 基本面引擎 | 排雷网：财务一票否决，综合打分 | 目标行业内个股池；**dropped_sectors 订阅** | 绝对干净的个股白名单（含状态字段）|
| 6. 战术层 | Ch06 信号引擎 | 发令枪：识别突破信号，管理 A/B/C 三容器信号 | 个股白名单；**含 whitelist_status** | 精确买卖信号；**含 signal_quality_score / historical_win_rate / historical_rr_ratio** |
| 7. 算力层 | Ch07 仓位管理 | 弹药库：凯利压缩，精确算股 | 买卖信号（**含质量字段**）与风险止损 | 具体下注股数（100股对齐）|
| 8. 执行层 | Ch08 状态机 | 终结者：GTSM 全局状态机，冰山拆单 | 合规交易 JSON；**EMERGENCY_OVERRIDE 通道** | 实盘订单 API 路由与成交审计日志 |

## 二、系统级绝对风控红线

> 以下红线必须写在底层拦截器（Interceptor）中，任何逻辑违反即触发内核级熔断。

### 暴露度控制红线

- **单笔风险熔断**：单笔交易最大绝对损失 ≤ 总资产净值的 **1%**
- **个股集中度**：单一股票名义本金总暴露 ≤ 总资产净值的 **10%**
- **行业集中度**：单一申万一级行业总暴露 ≤ 总资产净值的 **30%**
- **未脱险总敞口**：处于浮亏或止损未上移至保本线的总仓位风险 ≤ **5%**

### 物理执行与数学红线

- **凯利压缩原则**：`W_adjust` 仅做向下压缩，约束范围强锁在 **[0.1, 1.0]**，绝不允许放大 1% 初始风险
- **凯利输入来源**：`W_adjust` 必须由 Ch06 输出的 `signal_quality_score`、`historical_win_rate`、`historical_rr_ratio` 三个字段驱动计算，**禁止使用固定值**
- **物理手数量化**：最终执行股数必须是凯利调整后 `floor(shares / 100) × 100`
- **动态均价止损**：金字塔加仓后，止损线必须上移至 `max(初始止损价, 最新动态加权成本均价)`

### 加仓决策边界红线（V4.1 新增）

- **Ch06 职责**：仅输出 `add_position_permitted: true/false`，**禁止在 Ch06 中定义加仓比例数字**
- **Ch07 职责**：加仓股数的全部计算权力归 Ch07，Ch06 的 YES/NO 是唯一触发条件

## 三、全局异常与黑天鹅响应矩阵

| 异常触发场景 | GTSM 指令与系统动作 |
|---|---|
| 个股封死涨停（price ≥ limit_up）| 拒绝排队，放弃 VCP 突破信号，直接撤单归档，防炸板诱多 |
| 个股跌停开盘（price ≤ limit_down）| 绕过冰山拆单，09:29:59 用跌停价全仓抢跑集合竞价队列，断臂求生 |
| 系统性闪崩（指数30分钟跌 > 2.5% 或多于3只同步跌停）| 全局买入与加仓接口物理断电；GTSM 注入 **EMERGENCY_OVERRIDE** 信号，接管 Ch07 输出权限 |
| 柜台软失败（滑点过大或未成交）| 撤单并采用进攻性滑点补偿重新挂单，最多重试 **3 次**，超限即 DEAD_ORDER |
| 柜台硬失败（非法单位/资金不足）| 绝对禁止重试，抛出致命异常直接写入 DEAD_ORDER |

## 四、核心数据流与执行时钟

| 时段 | 系统行为 |
|---|---|
| 盘后结算（15:30–18:00）| AKShare 拉取全市场日线、财务、宏观数据；驱动 Ch02~Ch05，更新次日宏观预算、目标行业与个股白名单 |
| 盘前竞价（09:15–09:25）| 监控突发跌停黑天鹅，执行抢跑逃生逻辑 |
| 极速攻击期（09:30–09:45）| 停止大单冰山算法；仅允许突破追价与隔夜止损单 |
| **禁止交易窗口（09:30–10:00）**| **禁止新开仓信号执行**，消除开盘噪音污染 |
| 隐蔽潜行期（10:00–14:30）| 开启 TWAP/VWAP 大资金建仓路由，拆单间隔 3000ms–7000ms |
| 尾盘清扫期（14:50–14:57）| 撤销所有 PARTIAL_FILLED 残单，用集合竞价跨价单完成终极出清 |

## 五、V4.1 修订变更一览

| 优先级 | 涉及章节 | 修订内容 |
|---|---|---|
| P0 | Ch06→Ch07 | Ch06 输出 JSON 新增 `signal_quality_score`、`historical_win_rate`、`historical_rr_ratio`；Ch07 据此计算凯利系数 |
| P0 | Ch06 | 补充 B容器（红利防御）和 C容器（宏观对冲）的完整入场/出场信号规则 |
| P1 | Ch06/Ch07 | 统一加仓决策边界：Ch06 仅出 YES/NO，Ch07 负责全部股数计算 |
| P1 | Ch04→Ch05→Ch06 | Ch04 输出新增 `dropped_sectors` 字段；Ch05 订阅后将对应股票置为 `watchlist_suspended`；Ch06 拒绝该状态的新信号 |

| P2 | Ch08 | 极端盘面触发时 GTSM 注入 `EMERGENCY_OVERRIDE` 信号，明确接管 Ch07 输出优先级 |
