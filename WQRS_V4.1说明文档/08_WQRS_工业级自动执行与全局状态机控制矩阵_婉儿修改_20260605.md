## 8.3 核心大脑：全局交易状态机（GTSM）

每一笔进入第八章的总订单，必须分配全域唯一 `Master_Order_ID`，并在系统内存中注册对应的确定性有限状态机（DFA）。

### 8.3.1 状态全生命周期定义

| 状态 | 含义 |
|---|---|
| `PENDING` | 第七章信号刚送达，等待进入规范清洗 |
| `VALIDATED` | 通过第一层规范检查，冻结相应预算 |
| `SPLITTING` | 正在被拆单算法切割成子订单流 |
| `SUBMITTED` | 首笔或当前批次子订单已发送至券商柜台 |
| `PARTIAL_FILLED` | 子订单部分成交，剩余挂单驻留盘口 |
| `RETRYING` | 子订单超时未成，触发撤单，重试引擎重新计算补报 |
| `FILLED` | 所有子订单全部 100% 成交，状态归档 |
| `DEAD_ORDER` | 触及硬拒单、最大撤单红线或人工熔断，释放冻结资金，写入死单骨架 |
| `T1_LOCKED` | **V4.2 新增**：当日买入遭遇跌停，T+1 制度下无法卖出，标记次日抢跑 |

### 8.3.2 GTSM 全局状态（系统级）

除每笔订单的个体状态外，GTSM 维护一个系统级全局状态：

| 全局状态 | 含义 | 触发条件 |
|---------|------|---------|
| `NORMAL` | 正常运行 | 默认 |
| `ACTIVE` | EMERGENCY_OVERRIDE 已激活 | Flash Crash 触发（见 8.6） |
| `POST_EMERGENCY` | **V4.2 新增**：接管后观察期 | 退出条件全部满足（见 8.3.4） |

### 8.3.2.1 合法状态转移路径（个体订单级）

- **路径一（完美顺延）**：`PENDING → VALIDATED → SPLITTING → SUBMITTED → FILLED`
- **路径二（盘口震荡容错）**：`SUBMITTED → PARTIAL_FILLED → RETRYING → SUBMITTED → FILLED`
- **路径三（熔断断臂）**：`SUBMITTED / PARTIAL_FILLED → RETRYING(超限) → DEAD_ORDER`
- **路径四（紧急接管）**：`任意状态 → EMERGENCY_OVERRIDE → DEAD_ORDER（买入）/ 立即强制卖出`
- **路径五（T+1 锁定）**：**V4.2 新增** `当日买入 → T1_LOCKED → 次日集合竞价抢跑`

**任何非法状态跳跃（如 PENDING 直接跳到 FILLED）将触发操作系统级死机保护。**

### 8.3.3 EMERGENCY_OVERRIDE 接管机制（V4.1 新增，V4.2 闭环）

**触发来源**：8.6 极端盘面风控拦截网检测到系统性闪崩或多个持仓同步跌停。

**接管逻辑**：

```
1. GTSM 接收 EMERGENCY_OVERRIDE 信号
2. 全局状态从 NORMAL 切换至 ACTIVE
3. 立即冻结所有 BUY / 加仓操作（不论当前状态）
4. 中止 Ch07 的所有挂起输出（不再接收新的仓位JSON）
5. 将所有算力与 API 通道让渡给止损与清仓状态机
6. 写入审计日志：OVERRIDE_TRIGGERED，附带触发原因、时间戳、触发时沪深300点位
```

**与 Ch07 止损的时序关系**：
- **正常盘面**：Ch07 计算止损价 → Ch06 触发退出信号 → Ch08 执行卖出
- **极端盘面（跌停/闪崩）**：Ch08 的 GTSM 直接注入 EMERGENCY_OVERRIDE，**绕过 Ch07 的正常止损计算链路**，以最高优先级执行卖出，事后将该事件写入审计日志，反哺修正 Ch07 的滑点模型

### 8.3.4 EMERGENCY_OVERRIDE 退出机制（V4.2 新增 🆕）

**这是 V4.2 最重要的修复之一**。V4.1 的设计中，`emergency_override_active` 一旦设为 `true`，系统没有任何退出路径——相当于触发后永久性半身不遂。

#### 状态转移图

```
NORMAL ──[Flash Crash 触发]──▶ ACTIVE
                                 │
                    [30min + 4条件全满足]
                                 │
                                 ▼
                          POST_EMERGENCY
                         │              │
             [30min无事]  │              │ [再次触发]
                         ▼              ▼
                       NORMAL         ACTIVE

任意状态 ──[force_override_clear]──▶ NORMAL（人工强制解除）
```

#### 退出条件（全部满足时自动从 ACTIVE → POST_EMERGENCY）

```
1. 距离最近一次 EMERGENCY_OVERRIDE 触发 ≥ 30 分钟
2. 沪深300 较触发时点价格回升 ≥ 50%（收复一半以上失地）
3. 跌停个股数量 ≤ 1 只
4. 无新增跌停触发
```

每 30 秒检查一次退出条件。

#### POST_EMERGENCY 观察期规则（V4.2 新增）

ACTIVE 退出后不直接回 NORMAL，而是进入 30 分钟观察期：

| 限制项 | 规则 |
|--------|------|
| B 容器（股息价值） | 允许操作（防御型资产不受限） |
| D 容器（现金） | 允许操作（逆回购等） |
| A 容器（权益增长） | **继续冻结** — 禁止新开仓和加仓 |
| C 容器（宏观对冲） | **继续冻结** — 禁止新开仓和加仓 |
| 止损/清仓 | 正常执行（不限制卖出） |
| 持续时间 | 30 分钟 |

**观察期结束**：如未再次触发 EMERGENCY_OVERRIDE，全局状态自动恢复至 NORMAL，恢复至触发前的宏观状态下正常运行。

**观察期内再次触发**：直接回到 ACTIVE，计时器和条件计数器全部重置。

#### 人工强制解除

新增 `force_override_clear` 指令：

- 直接清除接管状态至 NORMAL
- **跳过 POST_EMERGENCY 观察期**
- 仅限授权通道发送（你的授权 token）
- 写入审计日志：`OVERRIDE_FORCE_CLEAR`，附带操作人、时间戳

#### 实现骨架（V4.2 更新）

```python
class WQRSTradeStateMachine:
    def __init__(self):
        self.master_registry = {}
        self.max_retries = 3
        self.global_state = "NORMAL"        # V4.2: NORMAL | ACTIVE | POST_EMERGENCY
        self.override_trigger_time = None
        self.override_trigger_price = None   # 触发时沪深300点位
        self.override_trigger_reason = None
        self.t1_escape_queue = []            # V4.2 新增：次日抢跑队列

    def inject_emergency_override(self, reason: str, trigger_price: float):
        """V4.2 更新：极端盘面接管入口"""
        if self.global_state == "ACTIVE":
            # 已在接管中，仅重置计时器
            self.override_trigger_time = time.time()
            return
        
        self.global_state = "ACTIVE"
        self.override_trigger_time = time.time()
        self.override_trigger_price = trigger_price
        self.override_trigger_reason = reason
        
        # 冻结所有 BUY 操作
        for m_id, meta in self.master_registry.items():
            if meta["side"] == "BUY" and meta["master_state"] not in ("FILLED", "DEAD_ORDER"):
                meta["master_state"] = "DEAD_ORDER"
                print(f"[EMERGENCY] {m_id} 被紧急接管，转为死单")
        
        self._write_audit_log("OVERRIDE_TRIGGERED", {
            "reason": reason,
            "trigger_price": trigger_price
        })
        
        # 启动退出条件检查定时器（每30秒）
        self._start_override_exit_monitor()

    def check_override_exit_conditions(self) -> bool:
        """V4.2 新增：检查 EMERGENCY_OVERRIDE 退出条件"""
        if self.global_state != "ACTIVE":
            return False
        
        # 条件1：持续时间
        elapsed = time.time() - self.override_trigger_time
        if elapsed < 1800:  # 30 分钟 = 1800 秒
            return False
        
        # 条件2：指数回升 ≥ 50%
        current_index = self._get_hs300_price()
        recovery_pct = (current_index - self.override_trigger_price) / abs(
            self._get_hs300_day_low() - self.override_trigger_price)
        if recovery_pct < 0.5:
            return False
        
        # 条件3：跌停个股 ≤ 1
        if self._count_limit_down_stocks() > 1:
            return False
        
        # 条件4：无新增跌停触发
        if self._has_new_limit_down_since_override():
            return False
        
        return True

    def exit_emergency_override(self):
        """V4.2 新增：进入 POST_EMERGENCY 观察期"""
        self.global_state = "POST_EMERGENCY"
        self.post_emergency_start = time.time()
        self._write_audit_log("OVERRIDE_EXIT_TO_POST_EMERGENCY", {})
        print("[OVERRIDE] 退出 ACTIVE，进入 POST_EMERGENCY 观察期（30分钟）")
        # 启动观察期结束定时器
        self._schedule_post_emergency_timeout()

    def complete_post_emergency(self):
        """V4.2 新增：观察期结束，恢复 NORMAL"""
        self.global_state = "NORMAL"
        self.override_trigger_time = None
        self.override_trigger_price = None
        self._write_audit_log("OVERRIDE_FULLY_RECOVERED", {})
        print("[OVERRIDE] 观察期结束，系统恢复 NORMAL 状态")

    def force_override_clear(self, auth_token: str):
        """V4.2 新增：人工强制解除接管"""
        if not self._verify_auth(auth_token):
            return
        old_state = self.global_state
        self.global_state = "NORMAL"
        self.override_trigger_time = None
        self.override_trigger_price = None
        self._write_audit_log("OVERRIDE_FORCE_CLEAR", {
            "previous_state": old_state
        })
        print(f"[OVERRIDE] 人工强制解除，从 {old_state} → NORMAL")

    def register_new_order(self, ch7_json):
        """接收第七章挂起信号，初始化 GTSM"""
        # V4.2：ACTIVE 和 POST_EMERGENCY 状态下均拒绝新 BUY
        if self.global_state in ("ACTIVE", "POST_EMERGENCY"):
            if ch7_json["order"]["side"] == "BUY":
                print(f"[{self.global_state}] 全局风控激活，拒绝新买入订单")
                return
        m_id = ch7_json["master_order_id"]
        self.master_registry[m_id] = {
            "code": ch7_json["asset"]["code"],
            "side": ch7_json["order"]["side"],
            "total_shares": ch7_json["order"]["total_shares"],
            "target_price": ch7_json["order"]["target_price"],
            "master_state": "PENDING",
            "child_orders": {},
            "retry_counts": 0,
            "filled_shares": 0,
            "buy_date": None,            # V4.2 新增：买入日期
            "holding_days": None          # V4.2 新增：持仓天数
        }
        self.process_state_engine(m_id)

    def process_state_engine(self, m_id):
        """状态机核心中央转移驱动逻辑"""
        order_meta = self.master_registry[m_id]
        state = order_meta["master_state"]

        if state == "PENDING":
            if order_meta["total_shares"] % 100 != 0 or order_meta["total_shares"] <= 0:
                order_meta["master_state"] = "DEAD_ORDER"
                print(f"[CRITICAL] {m_id} 股数非百股倍数，GTSM 击杀订单。")
                return
            order_meta["master_state"] = "VALIDATED"
            self.process_state_engine(m_id)

        elif state == "VALIDATED":
            order_meta["master_state"] = "SPLITTING"
            total = order_meta["total_shares"]
            K = 3
            base_child = math.floor(total / (K * 100)) * 100
            splits = [base_child] * (K - 1)
            splits.append(total - base_child * (K - 1))
            order_meta["splits"] = splits
            order_meta["master_state"] = "SUBMITTED"
            self.execute_next_child(m_id)

    def execute_next_child(self, m_id):
        """物理执行路由层"""
        order_meta = self.master_registry[m_id]
        if not order_meta["splits"]:
            order_meta["master_state"] = "FILLED"
            # V4.2 新增：成交后记录买入日期
            if order_meta["side"] == "BUY":
                order_meta["buy_date"] = datetime.date.today()
            print(f"[SUCCESS] {m_id} 全额成交，生命周期完美闭合。")
            return
        next_volume = order_meta["splits"].pop(0)
        print(f"[PHYSICAL] 发射子订单: {next_volume} 股, 标的: {order_meta['code']}")
        xt_id = "XT-" + str(random.randint(100000, 999999))
        order_meta["child_orders"][xt_id] = {"volume": next_volume, "status": "SENT"}

    def on_broker_callback(self, xt_id, broker_status, m_id):
        """券商异步回调，喂入 GTSM 中央大脑"""
        order_meta = self.master_registry[m_id]
        child = order_meta["child_orders"].get(xt_id)
        if not child: return

        if broker_status == "FILLED":
            child["status"] = "FILLED"
            order_meta["filled_shares"] += child["volume"]
            time.sleep(random.uniform(0.3, 0.7))
            self.execute_next_child(m_id)

        elif broker_status == "TIMEOUT_OR_FAILED":
            order_meta["master_state"] = "RETRYING"
            if order_meta["retry_counts"] >= self.max_retries:
                order_meta["master_state"] = "DEAD_ORDER"
                print(f"[风控熔断] {m_id} 重试超限，转为死单。")
                return
            order_meta["retry_counts"] += 1
            order_meta["splits"].insert(0, child["volume"])
            order_meta["master_state"] = "SUBMITTED"
            self.execute_next_child(m_id)

        elif broker_status in ("ERROR_INSUFFICIENT_FUNDS", "ERROR_INVALID_STOCK_CODE"):
            order_meta["master_state"] = "DEAD_ORDER"
            print(f"[HARD FAILURE] {m_id} 硬失败，禁止重试，直接死单。")
            self._send_alert(m_id, broker_status)

    def _write_audit_log(self, event_type: str, payload: dict):
        """审计日志写入"""
        import datetime
        log = {"event": event_type, "timestamp": datetime.datetime.utcnow().isoformat(), **payload}
        print(f"[AUDIT] {log}")

    def _send_alert(self, m_id: str, reason: str):
        """触发风控警报"""
        print(f"[ALERT] 订单 {m_id} 触发警报: {reason}")
```

## 8.5 第二层：智能拆单与分时路由引擎

### A股专用冰山对齐算法

**核心原则**：严禁粗暴除法切分，所有子单必须为100股整倍数。

```
设目标拆分笔数 K（默认 K=3）
Base = floor(Total / (K × 100)) × 100
前 K-1 笔 = Base
最后一笔 = Total - Base × (K-1)  # 自动消化余数
```

示例：2400股拆3笔 → 800 + 800 + 800，完全对齐。

### 时段分发调度矩阵（V4.2 统一修订版）

| 时段 | 名称 | 策略 | 说明 |
|------|------|------|------|
| 09:25-09:30 | 集合竞价执行期 | 仅执行隔夜跌停抢跑 + T+1 锁定抢跑，不参与正常竞价 | V4.2 新增：含 T+1 队列 |
| 09:30-09:45 | **极速止损期** | 仅允许隔夜持仓止损单执行，**禁止一切新开仓（含突破追价）** | **V4.2 修改**：删除原「突破追价」 |
| 09:45-10:00 | 噪音过滤期 | 禁止所有新开仓 | V4.2 明确化 |
| 10:00-14:30 | 冰山潜行期 | 随机 3000ms–7000ms 冰山脉冲路由，TWAP/VWAP | 不变 |
| 14:50-15:00 | 尾盘清扫期 | 强制撤单，14:56.500 集合竞价跨价单出清 | 不变 |

> **V4.2 核心变更**：原「极速攻击期 09:30-09:45 允许突破追价」与 Ch00 的「09:30-10:00 禁止新开仓」矛盾。现统一为：09:30-10:00 全程禁止新开仓。突破追价等待至 10:00 之后，通过冰山拆单执行。

## 8.6 第三层：极端盘面风控拦截网（V4.2 修订版）

### 涨停锁死诱多陷阱（Limit Up Shield）— 不变

- **触发条件**：`Ask_Price[0] ≥ Limit_Up_Price`（卖一价封死涨停）
- **拦截动作**：终止后续一切买入子单，对排队子单下达撤单，GTSM 强制转为 `DEAD_ORDER`
- **逻辑**：排队大概率遭遇尾盘炸板闷杀，低成交概率 + 高被收割风险，WQRS 拒绝参与

### 跌停生死一毫秒（Limit Down Survival）— V4.2 分层修订

#### 隔夜持仓（holding_days ≥ 1）— 原逻辑不变

- **触发条件**：持仓股 `Bid_Price[0] ≤ Limit_Down_Price`，且买入日期 ≠ 今日
- **拦截动作**：全面作废冰山规则，在 **09:29:59.999** 将所有持仓汇聚成单笔跌停价卖出单倾泻而出
- **时序说明**：此为 EMERGENCY_OVERRIDE 触发场景，绕过 Ch07 止损计算链路，GTSM 直接接管执行

#### 当日买入（holding_days = 0）— V4.2 新增 T+1 锁定机制 🆕

- **触发条件**：持仓股 `Bid_Price[0] ≤ Limit_Down_Price`，且买入日期 = 今日
- **T+1 制度约束**：当日买入的股票当日无法卖出
- **系统动作**：
  1. **不执行卖出**（T+1 制度禁止）
  2. 将该股票加入 `t1_escape_queue`（次日开盘自动执行队列）
  3. 写入审计日志：`T1_LOCKED`，附带股票代码、当前价格、锁定日期
  4. 第二天 09:29:59 自动执行集合竞价跌停价抢跑

```python
def handle_limit_down(self, stock_code: str, current_price: float, 
                      holding_days: int):
    """V4.2 修订：T+1 分层跌停处理"""
    if holding_days >= 1:
        # 隔夜持仓：原抢跑逻辑
        self._execute_limit_down_escape(stock_code)
    else:
        # 当日买入：T+1 锁定
        self._write_audit_log("T1_LOCKED", {
            "code": stock_code,
            "price": current_price,
            "reason": "当日买入遭遇跌停，T+1 制度下无法卖出",
            "next_action": "次日 09:29:59 集合竞价抢跑"
        })
        self.t1_escape_queue.append({
            "code": stock_code,
            "locked_date": datetime.date.today(),
            "lock_price": current_price
        })
        self._send_alert(None, f"T1_LOCKED: {stock_code} 当日买入遭遇跌停")
```

#### T+1 锁定分层总览

| 异常场景 | 当日买入（holding_days = 0） | 隔夜持仓（holding_days ≥ 1） |
|---------|---------------------------|----------------------------|
| 跌停开盘 | 标记 T1_LOCKED，次日 09:29:59 抢跑 | 09:29:59 跌停价全仓抢跑 |
| 盘中闪崩跌停 | 标记 T1_LOCKED，次日 09:29:59 抢跑 | 立即市价/跌停价清仓 |
| 连续跌停 | 再次标记，继续排队 | 首日已抢跑，剩余仓位继续抢跑 |

#### 每日开盘自动执行

09:25 集合竞价开始时，GTSM 自动遍历 `t1_escape_queue`，将昨日锁定的股票以跌停价全仓挂出卖单。执行完毕后清空队列并写入审计日志。

### 市场全域流动性枯竭（Flash Crash Melt-down）

- **触发条件**：沪深300/创业板指 30分钟内暴跌 **> 2.5%**，或持仓列表中多于 3 只个股同步触发跌停
- **拦截动作**：
  1. GTSM 注入 `EMERGENCY_OVERRIDE` 信号，全局状态 NORMAL → ACTIVE（见 8.3.3）
  2. 全局冻结所有 BUY 与加仓功能
  3. 全部算力与 API 通道让渡给清仓止损状态机
  4. **V4.2 新增**：启动退出条件监视器（见 8.3.4）

## 8.7 第四层：物理接口、死锁解锁与安全重试机制

### 软失败与进攻性滑点补偿（Soft Failure Retry）

- **定义**：子单发出后价格上行过快，超时未成（5秒），状态切入 `RETRYING`
- **解法**：
  1. 发出撤单指令，挂起等待券商返回 `ORDER_CANCELED` 回调
  2. 接收成功撤单后，新子单价格 = `Current_Latest_Price + 0.02`
  3. 重新下发，状态回 `SUBMITTED`
- **硬性计数器红线**：单一 Master 订单累计重试 **MAX_RETRIES = 3 次**，超限强制 `DEAD_ORDER`

### 硬失败原子化拒绝（Hard Failure Termination）

收到 `ERROR_INSUFFICIENT_FUNDS`、`ERROR_INVALID_STOCK_CODE` 或权限受限：

**绝对禁止重试！** 直接 `DEAD_ORDER`，触发系统级微信/钉钉风控警报。
