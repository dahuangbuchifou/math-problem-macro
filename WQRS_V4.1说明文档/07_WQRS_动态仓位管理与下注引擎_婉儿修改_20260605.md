## 7.1 核心定位

```
仓位系统 = 风险预算的物理化执行层
```

Ch07 是整个 WQRS 系统的"弹药库"：宏观决定是否交易，行业决定做哪个方向，基本面决定做哪只标的，信号决定何时进入，**仓位决定做多少**。

---

## 7.2 风险预算基础

```
R = Total_Asset × 1%
```

这是单笔交易的**最大允许亏损金额**，所有仓位计算以此为出发点。

---

## 7.3 核心仓位生成链（V4.2 修订版）

### Step 1：风险原始仓位

```
Shares_raw = R / ΔP
```

其中 `ΔP = 入场价 - 止损价`（来自 Ch06 的 `stop_loss_price`）

### Step 2：凯利调整（V4.2 五层保护完整版）

**2.1 输入取值（V4.2 更新）：**

```
p = historical_win_rate         （来自 Ch06 输出）
b = b_adjusted_for_limits       （优先使用 Ch06 新字段，若不存在则回退至 historical_rr_ratio）
q = 1 - p
```

> **V4.2 重要变更**：`b` 优先取 Ch06 的 `b_adjusted_for_limits`（已做涨跌停截断修正），该字段不存在时才使用原始 `historical_rr_ratio`。详见 Ch06 6.10 节赔率截断修正。

**2.2 体制转换检测（V4.2 新增）：**

在进行凯利计算之前，必须先检测当前胜率分布是否发生结构性变化：

```python
def detect_regime_change(win_rate_30d, win_rate_90d, historical_std):
    """检测胜率分布是否发生结构性变化（体制转换）"""
    deviation = abs(win_rate_30d - win_rate_90d)
    threshold = 1.5 * historical_std  # 约 93% 置信区间
    return deviation > threshold
```

| 参数 | 值 | 说明 |
|------|-----|------|
| 短期窗口 | 30 个交易日 | 反映近期胜率趋势 |
| 长期窗口 | 90 个交易日 | 反映长期胜率均值 |
| 偏离阈值 | 1.5 个标准差 | 平衡灵敏度与误报率 |
| 安全折扣 | ×0.7 | 体制转换期间仓位降至原计划 70% |

`historical_std` 按容器类型分别统计（A 成长/B 红利/C ETF 各自维护独立的胜率标准差）。

**2.3 凯利系数计算：**

```
Full_Kelly = (p × b - q) / b
Half_Kelly = Full_Kelly × 0.5        （安全压缩，保护层1）
W_adjust   = clamp(Half_Kelly, 0.1, 1.0)  （保护层2：防止极端值）

if regime_change_detected:
    W_adjust *= 0.7                   （保护层4：体制转换折扣）
    log_warning("Regime change detected, Kelly compressed by 30%")
```

**五层保护体系总览：**

| 层级 | 保护措施 | 作用 | 版本 |
|------|---------|------|------|
| 1 | Half Kelly（减半） | 降低估计误差敏感性 | V4.0 |
| 2 | clamp [0.1, 1.0] | 防止极端参数导致全仓/零仓 | V4.0 |
| 3 | 分容器独立统计 | A/B/C 各自维护胜率池，避免混淆 | V4.1 |
| 4 | 体制转换检测（×0.7） | p 发生结构性突变时自动降仓 | **V4.2** |
| 5 | 赔率截断修正（b 修正） | 涨跌停对 b 的扭曲 | **V4.2** |
| 6 | 最大下注 3% 上限 | 单笔绝对约束，不依赖凯利输出 | **V4.2** |

**W_adjust 含义：**
- `1.0` = 满额使用 1% 风险预算
- `0.1` = 极轻试探仓（信号质量极低时）

**与 signal_quality_score 的对应关系（用于校验，不替代计算）：**

| signal_quality_score | 典型 W_adjust 范围 |
|---|---|
| ≥ 90 | 0.75–1.00 |
| 80–89 | 0.55–0.75 |
| 70–79 | 0.40–0.55 |
| < 70 | 不接收信号 |

**禁止使用固定 W_adjust 值**，每笔信号必须通过上述公式动态计算。

```
Shares_kelly = Shares_raw × W_adjust
```

### Step 3：系统风控回写 + 最大下注上限（V4.2 新增）

必须通过 Portfolio Revalidation Engine，检查：

- 单股暴露 ≤ 10%
- 行业暴露 ≤ 30%
- 系统风险 ≤ 5%
- **单笔名义本金 ≤ 总资产 × 3%（V4.2 新增最大下注上限）**

任意一项超标 → 自动压缩 `Shares_kelly` 至合规值。

**最大下注上限逻辑（V4.2 新增，保护层6）：**

```python
MAX_SINGLE_BET_VALUE = total_asset * 0.03  # 单笔最多 3%

share_value = Shares_kelly * entry_price
if share_value > MAX_SINGLE_BET_VALUE:
    Shares_kelly = floor(MAX_SINGLE_BET_VALUE / entry_price / 100) * 100
    log_adjustment("max_bet_override", 
                   reason=f"单笔超 3% 上限，强制压缩至 {Shares_kelly} 股")
```

> **设计理由**：无论凯利公式算出多高的置信度，单笔下注不超过总资产 3%。这确保了即使凯利在体制转换中高估了 p 和 b，单次错误也不会造成灾难性损失。这是凯利保护体系中最硬的一道墙。

### Step 4：A股100股取整（最终执行）

```
Final_Shares = floor(Shares_kelly / 100) × 100
```

## 7.4 初始仓位结构

Ch06 的信号确认后，Ch07 计算的初始仓位为**目标仓位的 30%**（首笔建仓），剩余 70% 通过金字塔加仓机制分批入场。

---

## 7.5 金字塔加仓系统（V4.1 修订版，V4.2 维持）

### 触发条件

加仓的触发信号**唯一来源**是 Ch06 输出的 `add_position_permitted: true`，Ch07 不自行判断加仓时机。

**Ch07 在收到 `add_position_permitted: true` 后，还须同时验证：**
- 浮盈中（当前价 > 加权成本价）
- 当前价在 VWAP 上方
- 动态均价止损条件成立
- 风控重算通过（Step 3，**含 V4.2 新增的最大下注上限检查**）
- 体制转换检测通过（**V4.2 新增：体制转换期间可加仓，但仓位会因 ×0.7 折扣而自动压缩**）

**任意一项不满足 → 加仓拒绝，即使 Ch06 已发出 `true`。**

### 加仓比例结构（对应 Ch06 的触发阈值）

| Ch06 触发 | 加仓占目标仓位比例 | 说明 |
|---|---|---|
| 初始建仓 | 30% | 信号确认时 |
| 第一次许可（+8%浮盈）| 50% | 趋势确认加码 |
| 第二次许可（+15%浮盈）| 20% | 趋势延续末端 |
| **合计** | **100%** | 目标仓位全满 |

> 每次加仓的实际股数均通过凯利公式重新计算（使用最新的 `historical_win_rate`、`b_adjusted_for_limits` 和当前 `ΔP`），而非固定比例截断。

### 加仓强制规则

每次加仓必须执行：
- ✔ 重新计算凯利系数（含体制转换检测）
- ✔ 重新计算仓位占比
- ✔ 重新跑 Step 3 风控（含最大下注上限）
- ✔ 重新验证系统风险

### 止损规则（修复版）

```
Stop_Loss = max(初始止损价, 动态加权成本均价)
```

金字塔加仓后，止损线**必须上移**至新的动态均价，彻底根绝"账面保本、实际亏损"陷阱。

## 7.6 风险防火墙

| 约束 | 上限 |
|---|---|
| 单股暴露 | ≤ 10% |
| 行业暴露 | ≤ 30% |
| 系统风险（未脱险总仓位）| ≤ 5% |
| 单笔最大下注（V4.2 新增）| ≤ 总资产 3% |

以上约束为**硬性红线**，任何计算结果违反时系统自动回写压缩，不允许人工覆盖。

---

## 7.7 凯利系数的滚动更新机制

| 阶段 | p / b 来源 |
|---|---|
| 初期（< 90个交易日历史）| 使用 Ch06 的分级默认值（按 signal_quality_score 映射）；b 使用 `b_adjusted_for_limits`（若可用）或默认 b |
| 正式运行（≥ 90个交易日）| 使用实际滚动统计值，每日盘后更新；b 使用 `b_adjusted_for_limits` |

**分类统计**：A容器成长股、B容器红利股、C容器ETF 分别维护独立的胜率/赔率统计池，避免混淆。

### 体制转换检测的统计准备（V4.2 新增）

除 p 和 b 的均值外，每个容器还需维护：
- `win_rate_30d`：近 30 个交易日滚动胜率
- `win_rate_90d`：近 90 个交易日滚动胜率
- `win_rate_std_90d`：近 90 个交易日胜率的标准差（用于体制转换检测阈值计算）

## 7.9 本章终极结论

仓位系统 = 风险的物理执行器 + 数学约束终端 + 体制转换哨兵

**六层闭环：**

```
宏观     → 是否交易
行业     → 做哪个方向
基本面   → 做哪只标的
信号     → 何时进入（+加仓许可 YES/NO + 赔率修正）
仓位     → 做多少（凯利五层保护计算）
执行     → 是否成交
```

V4.2 核心升级：凯利计算增加**体制转换检测**和**最大下注上限**两道新防线，赔率输入升级为**涨跌停截断修正值**，形成六层保护体系。仓位管理引擎不再只是一个"能算对"的引擎，而是一个**在 A 股非线性环境中能活着**的引擎。
