## P0-1：交易窗口规则矛盾

### 问题描述

Ch00 总纲规定「09:30-10:00 禁止新开仓信号执行」，但 Ch08 执行引擎规定「09:30-09:45 极速攻击期允许突破追价与隔夜止损单」。同一时段两个模块说相反的话。

### 修改方案

**统一为三层窗口，彻底消除歧义：**

| 时段 | 名称 | 规则 | 说明 |
|------|------|------|------|
| 09:25-09:30 | 集合竞价 | 只执行隔夜跌停抢跑单 | 不参与竞价博弈 |
| 09:30-09:45 | 极速止损期 | **仅允许隔夜持仓止损单**（含跌停抢跑），**禁止一切新开仓（含突破追价）** | 开盘噪音最大，追价=送死 |
| 09:45-10:00 | 噪音过滤期 | 禁止所有新开仓 | 缓冲期，等待价格结构稳定 |
| 10:00-14:30 | 正常交易期 | 允许冰山拆单建仓，TWAP/VWAP路由 | 正常规则 |
| 14:50-14:57 | 尾盘清扫期 | 撤销所有残单，集合竞价出清 | 不变 |

### 修改涉及

- Ch00 总纲：四、核心数据流与执行时钟
- Ch08 执行引擎：8.5 第二层，时段分发调度矩阵

## P0-2：EMERGENCY_OVERRIDE 只进不出

### 问题描述

Flash Crash 触发后 GTSM 注入 `EMERGENCY_OVERRIDE`，冻结所有 BUY、接管 Ch07、让渡全部算力给清仓。但 `emergency_override_active` 一旦设为 `true`，**没有退出条件**，系统永久性半身不遂。

### 修改方案

**增加完整的状态机闭环：NORMAL → ACTIVE → POST_EMERGENCY → NORMAL**

#### 触发条件（不变）

1. 沪深300 30分钟内跌幅 > 2.5%
2. 或持仓中 > 3只个股同步触发跌停

#### 新增退出条件（全部满足时自动解除）

```
1. 距离最近一次 EMERGENCY_OVERRIDE 触发 ≥ 30分钟
2. 沪深300 较触发时点价格回升 ≥ 50%（收复一半以上失地）
3. 跌停个股数量 ≤ 1只
4. 无新增跌停触发
```

#### 退出后的过渡策略（POST_EMERGENCY 观察期）

- 退出 ACTIVE 后进入 **30分钟观察期**
- 观察期内仅允许 B容器（股息价值）+ D容器（现金）操作
- A容器（权益增长）和 C容器（宏观对冲）继续冻结
- 观察期结束后若未再次触发，自动恢复至触发前的宏观状态
- 观察期内若再次触发，直接回到 ACTIVE，计时器重置

#### 人工强制解除

新增 `force_override_clear` 人工指令，直接清除接管状态（跳过观察期）。仅限你本人通过授权通道发送。

### 状态转移图

```
NORMAL ──[Flash Crash触发]──▶ ACTIVE
                                 │
                    [30min + 4条件全满足]
                                 │
                                 ▼
                          POST_EMERGENCY
                         │              │
             [30min无事]  │              │ [再次触发]
                         ▼              ▼
                       NORMAL         ACTIVE

任意状态 ──[force_override_clear]──▶ NORMAL（人工豁免观察期）
```

### 修改涉及

- Ch00 总纲：三、全局异常与黑天鹅响应矩阵
- Ch08 执行引擎：8.3.3 EMERGENCY_OVERRIDE 接管机制、8.6 第三层

## P0-3：A股 T+1 同日买卖悖论

### 问题描述

跌停抢跑逻辑假设开盘即可卖出全部持仓，但 A股 T+1 制度下**当日买入的股票今日无法卖出**。如果今天建仓的股票盘中闪崩跌停，你只能看着。

### 分析

这个问题的实际严重程度有限，原因是：

1. **建仓时点保护**：WQRS 新开仓在 10:00 之后，而大多数跌停在开盘竞价或开盘几分钟内发生。如果一只股票开盘就跌停，WQRS 根本不会在 10:00 后对它发起买入。
2. **信号质量门槛**：WQRS 要求 VWAP 上方确认 15 分钟 + 分时量能 > 1.3×均值。满足这些条件的股票在当天内闪崩到跌停的概率极低。
3. **仓位分散**：首笔建仓仅占目标仓位 30%，单笔风险已控制在总资产 1%，即使遭遇极端情况，损失可承受。

**但概率低 ≠ 不需要处理。** 系统必须能应对黑天鹅。

### 修改方案：分层处理

#### 隔夜持仓（买入日期 ≠ 今日）

原有跌停抢跑逻辑**完全不变**：

- 集合竞价 09:29:59 跌停价全仓抢跑
- 绕过冰山拆单，直接倾泻

#### 当日买入（买入日期 = 今日）

新增 **T+1 锁定机制**：

```
动作序列：
1. 检测到持仓股跌停且 holding_days == 0
2. 无法执行卖出（T+1 制度限制）
3. 写入审计日志：T1_LOCKED，附带「次日抢跑」标记
4. 将该股票加入 t1_escape_queue（次日开盘自动执行队列）
5. 第二天 09:29:59 自动执行跌停价集合竞价抢跑
```

#### 补充到总纲风险矩阵

| 异常场景 | 当日买入（T+1 锁定） | 隔夜持仓 |
|---------|-------------------|---------|
| 跌停开盘 | **无法卖出，标记次日抢跑** | 09:29:59 跌停价全仓抢跑 |
| 盘中闪崩跌停 | **无法卖出，标记次日抢跑** | 立即市价/跌停价清仓 |
| 连续跌停（次日继续跌停） | **再次标记，继续排队** | 已在首日抢跑，剩余仓位继续抢跑 |

#### 制度性对冲（不能解决但能减轻）

1. **建仓时机保护**：新开仓全部在 10:00 之后，回避开盘跌停窗口
2. **仓位控制**：首笔建仓仅 30% 目标仓位，单笔上限 1% 风险，跌停亏损可控
3. **宏观过滤**：Risk Off/Panic/Capitulation 状态下禁止新开仓，从源头减少进入 T+1 锁定的概率
4. **质量筛选**：Ch05 的 Hard Filter + Accounting Red Flag 过滤掉高风险标的

### 修改涉及

- Ch00 总纲：三、全局异常与黑天鹅响应矩阵
- Ch08 执行引擎：8.6 第三层，跌停生死一毫秒

## P0-4：凯利公式在A股的适配问题

### 问题描述

凯利公式的三个核心假设在 A 股全部被违反：

| 凯利假设 | A股现实 | 后果 |
|----------|---------|------|
| 独立同分布（i.i.d.） | 体制转换频繁，牛熊切换时 p、b 突变 | 高估或低估真实胜率/赔率 |
| 无限可分割 | 100 股最低单位，floor() 取整 | 小账户偏差大，但影响有限 |
| 无摩擦/无截断 | 涨跌停限制、T+1、印花税 | b 的真实分布被截断 |

### 修改方案：不改凯利公式本身，加三层新保护

#### 已有保护层（保留不变）

| 保护层 | 作用 |
|--------|------|
| Half Kelly | 将 Full Kelly 减半，降低估计误差敏感性 |
| clamp [0.1, 1.0] | 防止极端参数导致全仓或零仓 |
| 分容器独立统计 | A 成长/B 红利/C ETF 各自维护胜率池，避免混淆 |

#### 新增第一层：体制转换检测（Ch07）

```python
def detect_regime_change(win_rate_30d, win_rate_90d):
    """检测胜率分布是否发生结构性变化"""
    # win_rate_std 从历史回测中估计（按容器类型分别统计）
    if abs(win_rate_30d - win_rate_90d) > 1.5 * WIN_RATE_STD:
        return True
    return False

# 在凯利计算前执行
if regime_change_detected:
    W_adjust *= 0.7  # 体制转换安全折扣
    log_warning(f"Regime change detected, Kelly compressed by 30%")
```

| 参数 | 值 | 说明 |
|------|-----|------|
| 检测窗口 | 30天 vs 90天 | 30天反映近期变化，90天反映长期均值 |
| 偏离阈值 | 1.5σ | 约对应 93% 置信区间，平衡灵敏度与误报 |
| 安全折扣 | ×0.7 | 体制转换期间仓位降至原计划的 70% |

#### 新增第二层：赔率截断修正（Ch06 信号输出 → Ch07 使用）

当止损价或目标价触及涨跌停时，理论赔率被涨跌停板截断，导致 b 高估：

```python
def adjust_b_for_price_limits(entry_price, stop_loss, target_price, 
                               limit_down, limit_up):
    """修正A股涨跌停对赔率的截断效应"""
    b_raw = (target_price - entry_price) / (entry_price - stop_loss)
    
    # 止损价触及跌停：真实亏损可能更大（次日在更低价成交）
    if stop_loss <= limit_down * 1.005:
        b_raw *= 0.80
        log_adjustment("stop_at_limit_down", factor=0.80)
    
    # 目标价触及涨停：真实盈利可能被涨停截断
    if target_price >= limit_up * 0.995:
        b_raw *= 0.90
        log_adjustment("target_at_limit_up", factor=0.90)
    
    return b_raw
```

#### 新增第三层：最大下注绝对上限（Ch07）

无论凯利公式算出什么结果，单笔下注不得超过总资产的 **3%**：

```python
# 在最终输出的 Shares_kelly 之后、floor(/100) 之前
MAX_SINGLE_BET_VALUE = total_asset * 0.03  # 单笔最多3%
if share_value > MAX_SINGLE_BET_VALUE:
    shares = floor(MAX_SINGLE_BET_VALUE / entry_price / 100) * 100
    log_adjustment("max_bet_override", reason="单笔超3%上限，强制压缩")
```

#### 五层保护总览

| 层级 | 保护措施 | 生效位置 | 版本 |
|------|---------|---------|------|
| 1 | Half Kelly（减半） | Ch07 凯利计算 | V4.0 原有 |
| 2 | clamp [0.1, 1.0] | Ch07 凯利计算 | V4.0 原有 |
| 3 | 分容器独立统计 | Ch07 统计池 | V4.1 原有 |
| 4 | 体制转换检测（×0.7折扣） | Ch07 凯利计算前 | **V4.2 新增** |
| 5 | 赔率截断修正（0.8/0.9折扣） | Ch06→Ch07 传递 | **V4.2 新增** |
| 6 | 最大下注 3% 上限 | Ch07 最终输出前 | **V4.2 新增** |

> 注：「五层保护」实为六个保护措施，其中前三个为保留项，后三个为新增项。名称沿用「五层」以保持与原文表述一致，实际含义为「五个层次的安全网」。

### 修改涉及

- Ch06 信号引擎：6.10 信号质量评分体系（增加赔率截断修正输出）
- Ch07 仓位管理：7.3 核心仓位生成链 Step 2（增加体制转换检测）、Step 3（增加最大下注上限）
- Ch00 总纲：二、系统级绝对风控红线（补充凯利保护层描述）

## 附加调整：SQLite 数据库方案确认

### 背景

大黄确认：数据库继续使用 SQLite，不变更。

### 分析

SQLite 在 WQRS 场景下完全够用：

| 考量维度 | SQLite 表现 | 是否够用 |
|---------|------------|---------|
| 数据量 | WQRS 全市场日线 + 财务 + 宏观，年增量 < 500MB | ✅ 轻松承载 |
| 并发 | WQRS 是单机单进程系统，无并发冲突 | ✅ 无瓶颈 |
| 查询性能 | 单表百万行内查询 < 50ms | ✅ 满足盘后批量计算 |
| 运维 | 零配置、零独立进程、文件备份 = 复制 | ✅ 适合个人使用 |
| 切换成本 | 未来如需迁移到 PostgreSQL，SQLAlchemy 兼容 | ✅ 无锁定风险 |

**唯一注意事项**：WAL 模式必须开启（磁盘写入性能提升 10-100 倍），已记录到 Ch00 数据工程规范中。
